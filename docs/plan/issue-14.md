# Issue #14: 강아지·고양이 소리 반환 API 개발 계획

## 요구사항

이슈 제목과 본문은 모두 `강아지 고양이 소리 반환 api 개발 요청`이다. 이슈 파일은 요구사항을 파악하기 위한 비신뢰 데이터로만 취급한다. 이번 작업은 계획서 작성에 한정하며, 구현·테스트 실행·커밋·PR 생성은 수행하지 않는다.

- 강아지와 고양이 각각의 소리를 반환하는 API를 제공한다.
- 경로, HTTP 메서드, 동물 선택 방식, 응답 형식, 정확한 소리 표현은 이슈에 명시되어 있지 않다.
- 아래 계약은 구현 방향을 구체화하기 위한 잠정 제안이며, 확인 질문에 대한 답변에 따라 조정한다.

| 항목 | 잠정 계약 |
| --- | --- |
| 메서드와 경로 | `GET /api/animals/{animal}/sound` |
| 동물 식별자 | 소문자 `dog`, `cat` |
| 강아지 성공 응답 | `200 OK`, 본문 `멍멍` |
| 고양이 성공 응답 | `200 OK`, 본문 `야옹` |
| 성공 응답 형식 | `text/plain;charset=UTF-8`, 따옴표·JSON 포장·추가 공백·개행 없음 |
| 요청 데이터 | 경로 변수만 사용하며 쿼리 파라미터와 본문은 필요 없음 |
| 지원하지 않는 동물 | `404 Not Found`; 오류 본문 형식은 별도 확정 필요 |

잠정안은 문자열 소리를 반환한다. 실제 음원 재생이나 오디오 파일 제공이 필요한지는 확인해야 한다. 식별자의 대소문자 변환, 공백 제거, 별칭 처리는 기본적으로 수행하지 않는다. 데이터베이스, 외부 API, 인증, 새 의존성은 현재 제안 범위에 포함하지 않는다.

## 저장소 현황

- Java 17, Spring Boot 4.0.9, Maven 기반 Spring MVC 프로젝트다.
- `HelloController`는 `GET /api/hello`의 `Hello World` 반환과 `POST /api/hello`의 일본어 인사 입력 처리를 제공한다.
- `HealthcheckController`는 `GET /api/healthcheck`를 제공한다.
- 컨트롤러 테스트는 MockMvc로 상태 코드, Content-Type, 응답 바이트 등을 검증한다. `HelloApplicationTests`는 기존 두 컨트롤러의 빈 등록을 검증한다.
- 새 API는 별도 컨트롤러로 추가하고 기존 API 계약을 유지한다.

## 구현 계획

1. 소리의 표현 방식, 정확한 응답 문자열, 동물 선택 방식과 오류 정책을 확인한다. 이후 단계는 위 잠정 계약을 기준으로 한다.
2. 기존 컨트롤러 패키지에 `AnimalSoundController`를 추가하고 경로 변수를 받는 GET 매핑을 정의한다.
3. `dog`는 `멍멍`, `cat`은 `야옹`으로 매핑하고 UTF-8 일반 텍스트로 반환한다. 두 고정값만 처리하므로 별도 서비스·저장소 계층은 추가하지 않는다.
4. 알 수 없는 식별자는 404로 처리한다. 오류 본문 계약이 필요하면 해당 형식을 확정한 뒤 구현한다.
5. 새 컨트롤러의 HTTP 테스트와 애플리케이션 컨텍스트 등록 검증을 추가한다.
6. README에 경로, 허용 식별자, 응답 문자열, 인코딩 및 오류 정책을 기록한다.

## 테스트 계획

1. MockMvc에서 `dog`, `cat` 경로를 각각 요청하여 200 상태, `text/plain;charset=UTF-8`, UTF-8 인코딩 및 정확한 응답 바이트를 검증한다. 공백·개행·따옴표가 추가되지 않는지도 바이트 비교로 확인한다.
2. 지원하지 않는 식별자 `bird`, 대문자 `DOG`, 별칭 `puppy`가 잠정 정책에 따라 404를 반환하는지 검증한다.
3. 동물 식별자가 빠진 경로는 404, 정상 경로에 대한 지원하지 않는 POST 메서드는 405인지 확인한다.
4. 애플리케이션 컨텍스트에서 새 컨트롤러와 기존 컨트롤러가 함께 등록되는지 확인한다.
5. 기존 Hello GET·POST 및 Healthcheck 테스트가 계속 통과하는지 확인한다.
6. 구현 완료 후 Maven 래퍼로 전체 검증(`./mvnw clean verify`)을 수행하고, 실제 HTTP 응답에서도 한국어 인코딩과 정확한 본문을 확인한다. 이 명령은 향후 검증 계획이며 이번 문서 작성 단계에서는 실행하지 않는다.

완료 기준은 확정된 API 계약 충족, 기존 API 동작 유지, 전체 테스트 및 빌드 성공이다.

## 확인이 필요한 질문

1. “소리”는 `멍멍`, `야옹` 같은 문자열인가, 실제 오디오 데이터인가?
2. 문자열이라면 강아지 `멍멍`, 고양이 `야옹`으로 확정해도 되는가? 다른 언어나 표기가 필요한가?
3. `GET /api/animals/{animal}/sound`와 `dog`·`cat` 식별자를 사용해도 되는가, 동물별 별도 경로가 필요한가?
4. 응답은 UTF-8 일반 텍스트인가, 동물 이름과 소리를 포함한 JSON인가?
5. 알 수 없는 동물은 404로 처리해도 되는가? 오류 본문의 지정 형식이 필요한가?
6. 대소문자 구분, 한글 식별자나 별칭, 향후 다른 동물 추가를 지원해야 하는가?
