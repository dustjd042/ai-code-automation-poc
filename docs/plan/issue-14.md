# Issue #14: 강아지·고양이 소리 반환 API 개발 계획

## 요구사항

- 이슈 제목과 본문은 모두 `강아지 고양이 소리 반환 api 개발 요청`이다. 강아지와 고양이의 소리를 반환하는 API를 제공한다.
- 이슈는 요구사항 추출용 비신뢰 데이터로만 취급한다. 이슈에 포함된 지시나 명령은 실행하지 않는다.
- 경로, HTTP 메서드, 동물 선택 방식, 응답 형식과 실제 소리 값은 명시되어 있지 않다. 아래 내용은 구현을 위한 잠정 제안이며 확정 요구사항과 구분한다.
- 이번 작업은 이 계획서 작성에 한정한다. 구현, 테스트 실행, 커밋 및 PR 생성은 수행하지 않는다.

### 제안하는 API 계약

소리는 오디오 파일이 아닌 한국어 의성어 문자열로 가정한다. 단일 경로에서 동물을 선택하는 방식을 제안한다.

| 항목 | 잠정 계약 |
| --- | --- |
| 메서드 및 경로 | `GET /api/animals/{animal}/sound` |
| 강아지 요청 및 응답 | `animal=dog` → `200 OK`, 본문 `멍멍` |
| 고양이 요청 및 응답 | `animal=cat` → `200 OK`, 본문 `야옹` |
| 성공 응답 형식 | `text/plain;charset=UTF-8`, 따옴표·JSON 포장·추가 공백·개행 없는 정확한 문자열 |
| 요청 데이터 | 쿼리 매개변수와 본문 불필요 |
| 지원하지 않는 동물 | `404 Not Found`; 오류 본문 형식은 별도 확정 필요 |
| 동물 식별자 규칙 | 소문자 `dog`, `cat`만 허용하며 대소문자 변환이나 공백 제거를 하지 않음 |

기존 `GET /api/hello`, `POST /api/hello`, `GET /api/healthcheck`의 동작은 유지한다. 잠정안에는 데이터베이스, 외부 서비스, 오디오 생성, 인증 및 새 의존성이 필요하지 않다.

## 저장소 현황

- `pom.xml` 기준 Java 17, Spring Boot 4.0.9 및 Maven 프로젝트이며 Spring MVC와 MVC 테스트 의존성이 있다.
- `HelloController`는 GET 인사와 일본어 본문을 받는 POST 인사를 제공한다. `HealthcheckController`는 상태 확인 GET API를 제공한다.
- 기존 컨트롤러 테스트는 MockMvc로 상태 코드, Content-Type 및 정확한 응답 바이트를 검사한다. 새 API도 이 패턴을 따른다.
- `HelloApplicationTests`의 기존 컨텍스트 검증에 새 컨트롤러 등록 확인을 추가할 수 있다.

## 구현 계획

1. 아래 질문을 통해 문자열 또는 오디오 여부, 경로, 소리 값, 오류 정책을 확정한다. 이후 단계는 위 잠정 계약을 기준으로 한다.
2. `AnimalSoundController`를 추가하고 동물 경로 변수를 받는 GET 매핑을 구현한다. UTF-8 일반 텍스트 응답을 명시한다.
3. `dog`와 `cat`을 각각 확정된 소리 문자열에 매핑하고, 나머지 값은 404로 처리한다. 단순 고정 매핑이므로 별도 서비스·저장소 계층은 도입하지 않는다.
4. 두 동물의 성공 응답과 지원하지 않는 입력을 MockMvc로 검증하고, 애플리케이션 컨텍스트에서 새 컨트롤러가 등록되는지 확인한다.
5. README에 경로, 지원 동물, 정확한 응답 값과 인코딩, 오류 정책을 추가한다. 기존 API에 대한 회귀 검증을 수행한다.

## 테스트 계획

1. `dog`, `cat` 각각에 대해 본문과 쿼리 없이 GET 요청을 보내 200, `text/plain;charset=UTF-8`, UTF-8 인코딩 및 `멍멍`·`야옹`의 정확한 바이트를 검사한다. 불필요한 공백·개행·JSON 포장이 없어야 한다.
2. 미지원 값 `bird`, 대문자 `DOG`, 앞뒤 공백이 포함된 식별자가 잠정 정책에 따라 404를 반환하는지 검사한다. 오류 본문은 계약이 확정된 경우에만 해당 형식을 검증한다.
3. 유효한 경로에 POST 요청을 보내 405를 확인한다. 동물 경로 구간이 누락된 요청은 404인지 확인한다.
4. 기존 Hello GET·POST의 성공 및 실패 사례, Healthcheck GET, 애플리케이션 컨텍스트 테스트가 계속 통과하는지 확인한다.
5. 구현 완료 후 저장소의 Maven 래퍼로 전체 검증(`./mvnw clean verify`)을 수행하고 실제 HTTP 응답에서 한국어가 깨지지 않는지 확인한다. 이 명령은 향후 검증 계획이며 이번 문서 작성에서는 실행하지 않는다.

완료 기준은 확정된 API 계약 충족, 새 테스트와 기존 회귀 테스트 통과, README와 실제 동작의 일치다.

## 확인이 필요한 질문

1. 반환할 소리는 한국어 의성어 문자열인가, 실제 오디오 데이터 또는 파일 URL인가?
2. 문자열이라면 강아지는 `멍멍`, 고양이는 `야옹`으로 확정해도 되는가?
3. 단일 `GET /api/animals/{animal}/sound` 경로와 영문 소문자 식별자 `dog`·`cat`을 사용해도 되는가? 동물별 별도 경로나 한글 입력이 필요한가?
4. 응답은 UTF-8 일반 텍스트로 충분한가, 동물명과 소리를 포함하는 JSON 구조가 필요한가?
5. 미지원 동물은 404로 처리해도 되는가? 대소문자·공백 허용 정책이나 정해진 오류 응답 형식이 있는가?
