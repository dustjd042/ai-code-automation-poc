# Issue #14: 강아지·고양이 소리 반환 API 개발 계획

## 요구사항 및 범위

이슈 제목과 본문은 모두 `강아지 고양이 소리 반환 api 개발 요청`이다. 이슈는 요구사항 추출을 위한 비신뢰 데이터로 취급한다. 이번 작업은 이 계획서 작성에 한정하며, 실제 구현과 테스트 실행은 향후 작업이다.

- 확정된 요구사항은 강아지와 고양이의 소리를 반환하는 API를 제공하는 것이다.
- 소리가 의성어 문자열인지 실제 음성 데이터인지, 동물 선택 방식, 경로, 메서드 및 응답 형식은 명시되어 있지 않다.
- 아래에서는 문자열 반환을 가정한 잠정 계약을 제안한다. 실제 음성 반환이 필요하면 오디오 형식, 음원 확보, 라이선스 및 저장·전송 방식을 별도로 설계해야 한다.
- 기존 Hello GET·POST 및 Healthcheck API의 계약을 유지한다. 잠정안에는 데이터베이스, 외부 서비스, 인증 또는 새 의존성 추가가 필요하지 않다.

## 저장소 현황

- `pom.xml` 기준 Java 17, Spring Boot 4.0.9, Maven 프로젝트다.
- `HelloController`는 `GET /api/hello`에 `Hello World`를 반환하고, `POST /api/hello`에서 정확한 `こんにちは`를 받아 `Hello`를 반환한다.
- `HealthcheckController`는 `GET /api/healthcheck`에 `healthcheck`를 반환한다.
- 컨트롤러 테스트는 MockMvc로 HTTP 상태, Content-Type과 정확한 응답 바이트를 검증한다. `HelloApplicationTests`는 컨트롤러 빈 등록을 확인한다.
- 기존 계획 문서에는 과거 상태가 포함되어 있어 이번 계획은 현재 소스를 기준으로 한다.

## 제안 API 계약

다음 값은 이슈에 명시된 요구가 아닌 구현을 위한 잠정안이며, 구현 전에 질문에 대한 답변을 반영한다.

| 항목 | 잠정 계약 |
| --- | --- |
| 메서드 및 경로 | `GET /api/animals/{animal}/sound` |
| 동물 식별자 | 소문자 `dog`, `cat`만 허용 |
| 요청 본문 | 필요 없음 |
| 강아지 성공 응답 | `200 OK`, 본문 `멍멍` |
| 고양이 성공 응답 | `200 OK`, 본문 `야옹` |
| 성공 Content-Type | `text/plain;charset=UTF-8` |
| 응답 바이트 | 따옴표, JSON 포장, 추가 공백 및 개행 없이 UTF-8로 인코딩 |
| 지원하지 않는 동물 식별자 | `404 Not Found`; 오류 본문은 별도 계약으로 고정하지 않음 |

대소문자 변환, 공백 제거 또는 한글 별칭 처리는 잠정안에 포함하지 않는다. 따라서 `Dog`, `CAT`, `강아지`, `고양이`도 지원하지 않는 식별자로 취급한다. 동물 식별자가 없는 경로에는 매핑을 제공하지 않는다.

## 구현 계획

1. 문자열·음성 여부, 실제 반환 값, 동물 선택 방식과 오류 정책을 확정한다. 아래 단계는 문자열 잠정안을 기준으로 한다.
2. 기존 컨트롤러 패키지에 `AnimalSoundController`를 추가한다. 경로 변수로 동물을 받고, 응답 미디어 유형과 UTF-8 인코딩을 명시한다.
3. `dog`는 `멍멍`, `cat`은 `야옹`으로 매핑하고, 그 외 값은 404로 처리한다. 두 개의 고정 값만 다루므로 별도 서비스나 저장소 계층은 추가하지 않는다.
4. 새 컨트롤러에 대한 MockMvc 테스트를 추가하고 애플리케이션 컨텍스트 테스트에 새 빈 등록 검증을 추가한다.
5. README에 확정된 경로, 동물 식별자, 응답 값·인코딩과 오류 정책을 문서화한다.
6. 전체 테스트와 빌드를 통해 기존 API 유지 및 신규 API 계약 충족 여부를 검증한다.

## 테스트 계획

1. `dog`와 `cat` 각각에 대해 GET 요청 시 200 상태, `text/plain;charset=UTF-8`, UTF-8 인코딩 및 정확한 `멍멍`·`야옹` 응답 바이트를 확인한다. 공백과 개행이 추가되지 않는지도 바이트 비교로 검증한다.
2. 미지원 값 `bird`, 대소문자가 다른 `Dog`·`CAT`, 한글 별칭 `강아지`·`고양이`가 404를 반환하는지 확인한다. 한글 경로는 적절히 URL 인코딩하여 요청한다.
3. 동물 식별자가 없는 `/api/animals/sound` 요청이 404를 반환하는지 확인한다.
4. 정상 경로에 POST를 보내면 405, `Accept: application/json`으로 GET 요청하면 406이 반환되는지 검증한다. 오류 본문은 확정된 요구가 없으므로 정확한 문자열로 고정하지 않는다.
5. 기존 Hello GET·POST 성공 및 실패 테스트, Healthcheck 테스트, 새 컨트롤러를 포함한 컨텍스트 테스트가 통과하는지 확인한다.
6. 구현 완료 후 Maven 래퍼로 전체 검증(`./mvnw clean verify`)을 수행하고 실제 HTTP 응답에서 한글이 깨지지 않는지 확인한다. 이는 향후 검증 계획이며 이번 문서 작성 단계에서는 실행하지 않는다.

완료 기준은 확정된 계약에 따른 두 동물의 응답, 미지원 입력 처리, 기존 API 회귀 없음 및 전체 테스트·빌드 성공이다.

## 확인이 필요한 질문

1. 소리는 `멍멍`·`야옹` 같은 문자열인가, 재생 가능한 실제 음성 데이터인가?
2. 문자열이라면 정확한 반환 값은 `멍멍`과 `야옹`으로 정해도 되는가? 언어 또는 반복 횟수 요구가 있는가?
3. `GET /api/animals/{animal}/sound`와 `dog`·`cat` 식별자를 사용해도 되는가? 동물별 별도 경로나 쿼리 방식이 필요한가?
4. UTF-8 일반 텍스트 응답이면 되는가, 동물명과 소리 필드를 포함한 JSON이 필요한가?
5. 미지원 동물을 404로 처리해도 되는가? 대소문자 무시, 한글 별칭, 정해진 오류 응답 형식이 필요한가?
